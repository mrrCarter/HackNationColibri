# Sauti Host scoped agent instructions — starter

Apply inside the Sauti repository after reconciling its existing root and nested instructions. This template does not replace Carther's global instructions or erase unrelated work.

## Product invariants

Core inference, analysis, drafting, decisions and approved queue work with all radios off. Network services carry messages/media only. Noor approves the exact authenticated action; edits void approval. Owner facts are versioned; counts are deterministic; every finding has validated exact evidence; uncertainty is explicit. Runtime models must have complete MIT/Apache-2.0 provenance.

## Lane ownership

- Codex Platform: root dependencies/lockfile, contract publication, sync/delivery, Azure/CI, sole main integration.
- Codex Mobile: apps/mobile and native runtime/persistence.
- Claude Domain: packages/core and domain tests; schema proposals reviewed with Platform.
- Claude Experience: experience/design/localization/voice assets, optional portal, demo docs.
- Max: contrib/max and agreed model/data manifests.
- Nat: contrib/nat and eval fixtures/results.
- Cosme: contrib/cosme and economics/customer evidence.
- Carther: scope, access, owner authority and demo/submission.

Use separate worktrees. One path owner; agree before touching another lane. Cross-review critical changes. Agents do not spawn overlapping builders or merge main independently. Platform changes shared contracts once, publishes revision/migration, and preserves consumers.

## Reuse

Inspect FencesNGates/AIdenID/Senti using Carther's authorized PC access. Record exact repo/path/commit/license/dependencies/tests/adaptation. No production PII, tokens or provider secrets in fixtures, git, APK, telemetry or room. A previous build is not evidence that a copied component passes current tests.

## Room and artifacts

Verify the existing Sauti room/account; hydrate bounded context before joining/writing. Use actual granted identities. ACK pinned revision once; claim lane once. Only blockers, decisions and handoffs need messages, normally 4–8 lines. Prefer threads/actions for questions/receipt; maintain artifact/checkpoint progress. No greetings, transcript heartbeat, ACK loops or full logs. Room reactions never authorize product actions.

## Verification

Run meaningful checks for changed invariants and complete required builds. No fake offline inference, fake delivery, invented metrics, unreviewed language described as validated, or silently loosened approvals. Error/unknown states remain truthful. Tests and builds can claim pass only with actual command/result/revision/device evidence.

## Deployment

Offline demo first. Azure services use actual authorized dev account/region, inspected resources, quota/cost plan and known spending cap. No blanket privileged role grants, destructive resets or production stress tests. Never deploy an unreviewed cloud-inference fallback to rescue the local product. Keys stay in private secret mechanisms. Keep final material scope decisions with Carther; proceed autonomously with routine reversible implementation.
